## 一、怎么启动

**Windows · 新设备（第一次跑）**：双击 **`首次安装.bat`** —— 自动装依赖、补 Electron 二进制、然后启动。

**Windows · 已经装过**：双击 **`start.bat`**。

**macOS · 新设备（第一次跑）**：双击 **`首次安装.command`** —— 自动找 Node、装依赖、补 Electron 二进制、然后启动。首次运行如果提示「无法验证开发者」，右键文件 → 打开。

**macOS · 已经装过**：双击 **`start.command`**。

> macOS 启动后会把运行日志写到项目目录的 `run.log`，关掉启动终端窗口不会带停程序。  
> 如果窗口一闪而过，说明 Electron 启动失败，先双击 `首次安装.bat` / `首次安装.command` 补齐依赖。  
> 命令行方式（mac）：`env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/Electron.app/Contents/MacOS/Electron .`

**打包成独立软件**：`npm run dist:mac`（出 .dmg/.app，支持 arm64 + Intel）或 `npm run dist:win`（Windows exe，需先 `npm i -D electron-builder`）。

启动后窗口分三块：左侧功能导航、中间配置面板、右侧抖音后台页面，底部是运行日志。

顶部地址栏带快捷站点下拉（只保留团购直播用得到的，选中即跳转）：

| 快捷入口          | 地址                         |
| ------------- | -------------------------- |
| 抖音生活服务 eos 后台 | `https://eos.douyin.com/`  |
| 抖音生活服务商家后台    | `https://life.douyin.com/` |

也可以直接在输入框粘任意地址回车，或选「自定义地址…」。下拉框会自动跟随当前访问的站点。

右侧页面区支持**分栏**：点工具条上的「＋ 分栏」可以并排再开一个页面（每个分栏有自己的地址栏和刷新/关闭按钮），方便一边看中控台、一边看别的页面。第一个栏标着**主控**，所有自动化功能（弹讲解/发评/回复/优惠券）只作用于主控栏；分栏仅用于查看。

## 二、⚠️ 第一次使用必须做：绑定选择器

**这一步不做，什么功能都跑不起来。** 抖音后台的 class 名是随机哈希、会随版本变化，所以选择器全部可配置。

点左侧 **⑤ 选择器校准**，三种方式任选：

| 方式        | 适用场景                             | 怎么做                                        |
| --------- | -------------------------------- | ------------------------------------------ |
| **① 直接填** | 手上已经有 class（看代码、看 DevTools、别人给的） | 把类名粘进输入框即可，不用开直播间                          |
| **② 拾取**  | 页面上能看到目标元素                       | 点字段右边「拾取」→ 在右侧页面单击目标元素，自动回填（会同时生成 2~4 种写法） |
| **③ 扫描**  | 不确定 class 叫什么                    | 选好「绑定到」→ 点「扫描当前页」→ 在列表里点一下对应元素             |

### 一个字段可以填多行

多行 = 多个候选，**从上往下依次尝试，第一个命中的生效**。抖音改版一般只换 class 而不改文案，所以推荐这么写：

```
text=讲解          ← 最稳，放第一条
.live-explain-btn  ← 旧版 class，留着当备选
[data-e2e="explain"]
```

### 支持的写法

| 写法     | 例子                                        | 说明                               |
| ------ | ----------------------------------------- | -------------------------------- |
| 裸类名    | `live-buy-7Zq`                            | 自动当成 `.live-buy-7Zq`             |
| 类名片段   | `class=live-buy`                          | 模糊匹配，哈希后缀变了也能命中                  |
| 文本     | `text=讲解`                                 | 按元素文字找，最抗改版                      |
| XPath  | `xpath=//button[2]` 或直接粘 `//div[@id="x"]` | DevTools 里「Copy XPath」直接可用       |
| 原生 CSS | `.list > button:nth-of-type(3)`           | 也支持 `#id`、`[data-index="{{n}}"]` |
| 整段属性   | `class="live-btn primary"`                | 从 DevTools 复制粘贴也能自动识别            |

### 需要绑定的字段

| 字段         | 指向什么             | 提示                                              |
| ---------- | ---------------- | ----------------------------------------------- |
| 团购卡 / 商品卡片 | 列表里单个团购卡的整块区域    | 如果卡片有固定序号属性，写成 `[data-index="{{n}}"]` 这类带占位符的形式 |
| 卡片内「讲解」按钮  | 卡片上触发弹窗的那个按钮     | **文案可能是「讲解」「弹卡」「上架」，按实际页面确认**                   |
| 评论输入框      | 公屏底部的输入框         | 通常是 `textarea` 或 `div[contenteditable]`         |
| 发送按钮       | 输入框旁的发送键         | 留空则用回车发送                                        |
| 置顶按钮       | 发评后的置顶操作         | 不需要置顶可留空                                        |
| 单条评论容器     | 公屏里一条评论的整块区域     | 必填，回评靠它定位                                       |
| └ 评论文本     | 容器内的正文节点         | 填了才能做关键词匹配                                      |
| └ 评论昵称     | 容器内的用户名节点        | 用于去重和 @ 回复                                      |
| └ 回复按钮     | 容器内的「回复」按钮       | 留空则在公屏直接 `@昵称` 回复                               |
| 在线观众容器     | 观众列表里单个观众        | 欢迎语靠它检测新人                                       |
| └ 观众昵称     | 容器内的昵称节点         |                                                 |
| 成交/下单提示条   | 弹出「xxx 下单了」的提示元素 | 用于触发感谢语，不做可留空                                   |

**没把握就先点「填入常用候选」**，程序会把常见的 `text=`、`[class*=]` 写法填进空字段，再用「全部测试」看哪些命中。

**绑定完必做一次验证**：右上角打开 **「试运行」** 开关 → 点「全部测试」→ 看日志里每个字段命中了几个候选、命中的元素长什么样。试运行模式下所有动作只写日志、不真点，安全。

日志长这样，一眼能判断对不对：

```
✓ 卡片内「讲解」按钮：命中 text=讲解（第 1/3 个候选）→ <BUTTON>「讲解」
　该元素 class：live-buy-7Zq primary
✗ 单条评论容器：3 个候选都没命中 —— [class*="comment-item"] ／ [class*="commentItem"] ／ ...
```

## 三、四个功能怎么用

### ① 弹窗循环

按节奏反复触发团购卡的讲解/弹窗，让卡片刻度停留在直播画面上。

- **循环内容**：每行一个团购卡序号（1、2、3…）或卡片名称；顺序就是播放顺序
- **弹窗显示时长 / 消失后停留**：两个相加就是每张卡的占用时间
- **循环轮数**：0 = 无限循环，填 3 = 所有卡走完 3 遍自动停
- **播放顺序**：可以选"每轮随机打乱"，比固定顺序更自然

建议参数：显示 6 秒、停留 3 秒起，跑一场看实际效果再调。

### ② 自动发评

把卖点、优惠、引导话术预设成"评论组"，开播后按节奏自动轮发。

- **单次轮评时长**：一轮发多久（比如 2 分钟）
- **每条间隔**：5~9 秒这种区间写法，程序会在区间内随机
- **休息时长**：一轮结束后停几分钟再开始下一轮
- **自动置顶**：内容前加 `[置顶]` 前缀，表示这条发完尝试置顶；配合"置顶间隔"控制频率

### ③ 关键词回评

扫公屏新评论，命中关键词就自动回复。规则一行一条：

```
怎么核销|怎么用 => 拍下后在订单里点开团购券，到店出示二维码核销就行~
几点开门|营业时间 => 每天 10:00-22:00，节假日不休息
还有票吗|有货吗 => 还有的，库存有限，先拍先得
```

- `|` 分隔同义词，`=>` 后面是回复内容
- **相似评论间隔**：同一类问题 N 秒内只回一次，防止同一句话刷屏
- **延迟回评**：命中后等 N 秒再回，比秒回更像真人
- 启动时**第一次扫描只建立基线**，不会把开播前的历史评论全部回一遍

### ④ 欢迎语 / 成交感谢

- **欢迎语**：定时比对在线观众列表，出现新人就发欢迎语，`{name}` 会替换成昵称。每次最多欢迎 3 个人，避免瞬间刷屏
- **成交感谢**：监听成交提示条，出现新内容就发感谢语

## 四、风控相关（重要）

这是通过**模拟操作网页后台**实现的第三方工具，不是官方接口。抖音平台规则不鼓励这类操作，**存在限流、功能受限甚至账号处罚的风险**，请自行评估。

降低风险的做法：

- 单字输入间隔保持 55~175 毫秒，别调到 20 毫秒以下（那是机器速度）
- 发评间隔不要低于 5 秒，一场直播别长时间高频刷评
- 弹窗循环别用固定节奏，留一点点抖动（程序默认 ±6%）
- 新号首播不要一上来四个功能全开
- 后台操作期间不要同时手动操作同一账号，容易冲突

**出问题本工具不承担责任。**

## 五、常见问题

### 1. 在来客里点「直播中控」跳到了别的浏览器 / 新开了一个窗口，拾取用不了

**已修复。** 原因是这类按钮走的是 `window.open`，浏览器默认会另开窗口，而自动化脚本只注入在内嵌页面里，所以那个新窗口完全不受控。

现在的处理方式是：**拦截弹窗，把地址改成在当前内嵌页面里打开**。日志里会看到一行 `[guest] 拦截弹窗，改为内嵌导航：...`，页面在右边直接跳过去，拾取就正常了。

### 2. 拾取时鼠标移上去没有蓝色边框

按顺序排查：

1. 点左侧「⑤ 选择器校准」→「**检查页面结构**」，看日志里框架数量
   - 显示 **1 个框架**：说明页面还停在来客首页，需要先点进直播中控台
   - 显示 **2 个以上**：中控台在 iframe 里，程序已经支持，继续第 2 步
2. 确认右侧页面已经加载完（标题栏不是「加载中…」）
3. 如果点击后直接跳转了，说明你点到了链接上 —— 拾取模式虽然会阻止默认行为，但个别元素例外，换个位置点试试

### 3. 选择器填了但「测试」显示未命中

- 中控台可能是 **懒加载**：列表还没滚动/渲染出来，元素不存在。先把页面滚到底、等数据出来再拾取
- class 名带随机哈希时，改成 **`text=xxx`** 按文案找，稳得多；或写 `class=类名前缀` 做片段匹配
- 卡片类元素建议手改成带占位符的形式，例如 `[data-index="{{n}}"]`，这样一次绑定全卡通用

### 4. 页面白屏或提示「请使用最新版浏览器」

程序已经把 UA 伪装成 Chrome 138。如果仍然白屏，先点右上角「↻」刷新；还是不行就把日志导出发我。
