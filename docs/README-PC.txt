一、怎么跑起来

【macOS】
1) 双击「首次安装.command」（装依赖 + 补 Electron 二进制，只需一次）
2) 双击「start.command」启动

【Windows】
1) 装 Node 20+（建议 22）
2) 双击 install.bat（装依赖；国内会自动走 npmmirror 镜像）
   如果 Electron 二进制没下下来，在该目录手动补：
      set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
      node node_modules/electron/install.js
3) 双击 start.bat 启动（或 npm start）

二、改完必须自测（全过再交付）

      npx electron test/ui-test.js        界面，29 项（不需要登录）
      npx electron test/auto-test.js      注入/选择器，42 项（不需要登录）
      npx electron test/worker-test.js    后台页，17 项（必须开播才有意义）
      npx electron test/scheme-guard.js   外部协议拦截，8 项（不需要登录/开播）
      npx electron test/live-ui.js        日志页签/统计/运行中位置，16 项（要登录，只读不提交）
      npx electron test/live-refresh.js   后台刷新不波及前台，8 项（要登录 + 开播）
      npx electron test/live-all.js 150   并发压测：四功能同开，看谁被饿死（要登录 + 开播）

   live-all.js 会先备份 data/config.json，注入「不真发券 / 不补库存 / 发评间隔拉长」的测试配置，
   跑完自动还原。报告会给：页面独占是否成立、最长饿死时间、各功能产出、谁中途退出、错误分布。

   下播时 worker-test 里「抓商品 / room_id / 评论」相关几项会失败，属正常。

三、这个版本的关键约束（踩过坑，别改坏）

· 自动化只跑在「后台页」（看不见的第二页面）。任何时候都不许导航 / 点击 / 滚动主界面。
· PAGE.target() 在 background 模式下永远返回 worker；后台页起不来就等待重试，不退回 main。
· 所有会动页面的动作必须走 PageBus（withTask / withPage）。裸调 click/type/导航 = 必然抢页面。
· 临界区要尽量小。任何「等 10 秒以上」的等待（比如发券间隔）必须放在锁外，否则别的功能全被饿死。
· 收尾（closeOverlays / 回中控台）必须在【还锁着】的时候做完，先 release 再收尾会误关下一个任务的面板。
· 刷后台页前要确认没人正在动页面（PageBus 空闲），否则会把跑到一半的任务毁掉。
· tp-lib 不要无条件重复注入（guest.ensureLib 已按版本判重）；否则 fetch/XHR 会被反复包层，
  跑一阵子页面就卡死——这是之前"越跑越坏"的根因。
· 抖音评论区在隐藏页面会暂停刷新，所以「读评论」必须走 main。
· main.js 有单实例锁：调试时别指望开两个窗口对比，第二个会被拉回第一个。

四、目录说明

· src/app.js      界面 + 全部调度逻辑（约 4700 行，最大的文件）
· src/index.html  界面骨架 + 注入到网页里的 tp-lib（readList / apiComment / locate 等）
· src/styles.css  全部样式（左栏：功能菜单 → 运行中 → 累计；底部日志 4 行）
· guest.js        内嵌页面操作层（CDP 真实点击、多页面注册、按需注入）
· main.js         主进程（窗口、IPC、菜单、急停快捷键、单实例锁）
· data/config.json 开发机上的真实配置（含测试数据，不随包发）
· data/config.default.json 出厂干净模板（随包发；商品/券/秒杀/评论/统计全空，选择器保留）
· scripts/make-default-config.js 重新生成出厂模板 + --check 校验有没有残留
· HANDOVER.md     完整交接文档（含 v0.9.2 → v0.10.8 的改动记录）
· test/           自测脚本（ui / auto / worker / scheme-guard + 真机 live-ui / live-refresh / live-all）

五、当前状态（v0.10.8）

· 六大功能：弹讲解（含常驻单卡）、自动发评（含置顶）、发优惠券、秒杀监控/投放、欢迎语、感谢语。
· 抓数据只有一个总入口：「商品」页的「⚡ 同步全部」（结构识别 + 商品 + 券 + 秒杀入口一次抓完）；
  券页「↻ 只扫券」、秒杀区「↻ 只扫入口」、商品页「↻ 只抓商品」是单项补抓，只动自己那一块。
· 新增「实时数据」页（第⑤个）：抖音侧大屏（在线/累计观看/涨粉/成交/GMV/观看→支付）
  + 单品表（曝光/点击/点击率/成交/GMV）。只读，可以和所有功能同时开，10 秒刷新。
· 新增接口通道（设置里可关）：
  - 商品列表走货架接口，一次拿全量，不再滚动页面 → 自动刷新商品不再打断弹讲解
  - 弹讲解走 card/switch 接口，不点画面、不占调度 → 发评/发券/秒杀可以真正并行
  - 空闲保活：每分钟一次只读请求，防止长时间挂机被踢
  - 官方抽屉/弹窗打开时自动让位，关掉再继续（避免点在遮罩上"成功但没效果"）
· 「设置 → 数据」有「清空业务数据」：交机/换机前一键清掉商品、券、秒杀卡、评论话术、统计，
  选择器和调度保留。
· 「设置 → 内存」能看到每个进程各占多少（主界面 / 后台页分别标名），也有两个回收动作：
  「清理内存缓存」（只清日志和扫描结果，不停直播）和「重建后台页」（回收最多，会中断当前动作）。
  界面 + 后台页各是一整个抖音直播间，合计 1GB 上下是正常量级。
· 左栏自上而下：功能菜单 → 运行中（每个任务一个 × 可单独停）→ 累计统计；运行日志固定在底部 4 行。
· 日志按功能分页签（全部/弹讲解/发评/发券/秒杀/商品/系统），连续重复合并为 ×N。
· 累计统计（弹讲解/发评/发券/秒杀/后台刷新/失败）存 config.json，跨会话累加，可一键清零。
· 发券：间隔 = 券有效期 + 到期后等待；真实发放间隔的等待已在页面锁之外，不再堵住其它功能。
· 发评：接口优先，失败自动改走页面输入；连续 3 条发不出去会暂停 60 秒（多半是下播了）。
· 自动回复（关键词回评）已按你的要求整块删除。
